Sovereign Self-Healing

LLM routing and AI SRE triage on OpenShift AI

When an application breaks, an AI SRE agent investigates it: metrics, logs, a diagnosis and an incident ticket. Every LLM call of the agent goes through a sovereign router. Sensitive data stays on a GPU in the cluster. Only clean and complex work goes to an external model.

How it works

Agents investigate. The router protects the data.

AI agents are useful for operations, but they read everything: logs, metrics, tickets, customer data. This demo shows how to use them without sending that data to an external model by default.

01

Something breaks

A demo application runs in three namespaces. It returns errors and some slow answers. Prometheus sees the errors, and Alertmanager fires an alert for the namespace.

02

An agent investigates

The AI SRE agent of that namespace gets the alert. With MCP tools it reads metrics, pod lists and logs. It writes a diagnosis and opens an incident.

03

The router decides

Every LLM call goes through one endpoint. Four gates decide: the local model on the cluster GPU, or the external SOTA model. Requests about restricted namespaces, and requests with sensitive data, stay on the local model.

Each example is a real request of the demo, with the real reasons from the router's log. The first gate that says LOCAL decides, and the gates after it do not run. Pick an example, or let the page show them one after the other.

Keys: ← → on the buttons, N and P on the page

The four gates

1 NAMESPACE A request that names a namespace labelled restricted stays local. No other gate runs.

2 EFFICIENCY Short and simple requests (without a keyword such as analyze or compare), requests over the SOTA size cap, and requests from a team that has used up its SOTA token budget stay local.

3 PRIVACY Rules (IBAN, cards, tax codes), lexicons and a decision model look for sensitive data. If a detector fails, the request stays local.

4 TIERING Some teams may use only the local model, for example the legal team.

Why it matters

The agents send large contexts: tool output, logs, metrics. A request can carry customer data without anyone noticing. The router checks the whole request, including the system prompt and the tool output, before any data goes out.

Every decision is logged and traced, so you can always answer the question: which data left the cluster, and why?

    What happens

    The alert reaches the ogx-alert-translator, which calls the agent of the alert's namespace. The agent works in turns: the model asks for a tool call, the tool answers, and the model decides the next step.

    The agent uses three MCP servers, all in the cluster: Prometheus for metrics, OpenShift for pods and logs (read-only), and the ticketing system. At the end it opens an incident with its diagnosis.

    Each LLM turn is a normal request to the router, like the requests of any other client: same gates, same logs, same traces.

    Traces

    Every decision is a trace

    The router sends OpenTelemetry traces to Tempo in the cluster. The namespace, efficiency and privacy gates are child spans of router.chain, with their verdict and reason. Click a span to read its attributes.

    Architecture

    What runs where

    Everything runs on one OpenShift cluster on AWS, with two GPU nodes. Only the external SOTA model is outside. Hover over a component, or reach it with the Tab key, to read what it does.

    Dashboards

    See it in the OpenShift console

    Perses dashboards in the console show where the requests went, which gate decided and how busy the GPUs are. A live page shows every decision as it happens.

    MLflow PREVIEW

    A record of every investigation

    Red Hat MLflow, part of OpenShift AI, can record every investigation of the agent: each LLM turn, each tool call, the tokens and the time. A local judge model can score the diagnosis. This part was tested in a short experiment and is not in the default install yet: read the results.

    Try it

    Install it on your cluster

    One Ansible playbook installs the operators with pinned versions, prepares two GPU nodes and seeds Argo CD. Argo CD deploys everything else from git. A full install takes about 40 to 60 minutes; a validation playbook checks the result.

    Read the install guide 
    git clone https://github.com/sovereign-selfheal/ansible.git
cd ansible
uv sync
uv run ansible-galaxy collection install -r requirements.yml
scripts/run-playbook.sh playbooks/site.yml
