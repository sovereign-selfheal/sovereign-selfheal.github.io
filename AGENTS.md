# AGENTS.md — `sovereign-selfheal.github.io` repository

Guidance for AI coding agents and humans working in this repo. Read it before you change anything.

## 1. Purpose

The public site of the demo *"Sovereign Self-Healing: LLM Routing and AI SRE Triage on OpenShift AI"*,
served by GitHub Pages at <https://sovereign-selfheal.github.io/>. It explains the demo and links the
install guide. It installs nothing and changes no cluster.

## 2. Rules

- **Public by design.** Everything here is on the internet. Never add host names of a cluster, tokens,
  API keys, IP addresses, e-mail addresses or user names. Never add prompts or answers of the agents, or
  the text of an incident (it is written by the agent's model). The only prompts allowed are the ones
  of validation cases: synthetic test data, already public in the validation repo (the scenario keeps
  the case id). `tools/check_site.py` enforces these rules.
- **Raw data stays outside.** `tools/capture.py` writes outside the repository; `tools/sanitize.py`
  copies only an allowlist of fields into `data/*.js`. To show a new field, add it to the allowlist in
  `sanitize.py` on purpose; never copy whole log lines or spans.
- **Nothing from other sites.** No CDN, no fonts from other sites, no analytics, no external images or
  scripts (the Red Hat fonts are in `fonts/`, SIL Open Font License). The
  Content Security Policy in every page must keep `default-src 'self'` and `script-src 'self'`. Links
  (`<a href>`) to other sites are fine.
- **No build step.** Plain HTML, CSS and JavaScript (ES2020, no modules), so GitHub Pages serves the
  files as they are and the page works from `file://`.
- **Two themes.** Every color is a CSS variable of `css/site.css`, defined for the dark and the light
  theme. Scripts and SVG use classes, never color values (`check_site.py` fails on a color literal in
  `js/`). Check both themes after a change.
- **Accessibility.** Every widget works with the keyboard, has a static view for
  `prefers-reduced-motion`, and fits a 375 px screen without horizontal scroll.
- **Run `tools/check_site.py` before every commit.** The CI runs it too. Leak patterns live in
  `tools/leaks.py`, shared by `sanitize.py` and `check_site.py`; keep them generic (no name of a
  single cluster).
- Text in **English**, level B2/C1: short, clear sentences, no idioms.
- **Python tools with uv**, never pip (`tools/pyproject.toml`, `tools/uv.lock`).

## 3. Layout

```
index.html, install.html, 404.html   pages
css/site.css                         the only stylesheet: black, white and red for the page; teal (LOCAL),
                                     amber (SOTA) and rose (restricted) only inside the widgets
fonts/                               Red Hat Display, Text and Mono (variable woff2, OFL.txt)
js/common.js                         helpers: element creation, travel(), runner, visibility
js/simulator.js, replay.js,          one script per widget; each reads one window.DEMO.<name>
  waterfall.js, archmap.js
data/*.js                            generated by tools/sanitize.py, except components.js (by hand)
img/                                 screenshots without metadata (check_site.py --strip-png)
tools/                               capture.py, sanitize.py, check_site.py, picks.json
```

## 4. Contract with the other repos

- The routing chain, its gate names and reason strings come from the `router` repo (the version is
  in `tools/picks.json`, `router_version`). When the router changes its gates or its log line, capture
  new data and update `js/simulator.js` if the gates changed.
- The investigation and the traces depend on the span names of the router (`router.chain`, `gate.*`,
  `litellm_request`) and on the log lines of the triage agent and of the ogx-alert-translator.
- `install.html` summarizes the README of the `ansible` repo. When the install changes there, change
  the summary here.
- `data/components.js` names the repositories of the organization. Add a new repository there and in
  the list of `index.html`.
