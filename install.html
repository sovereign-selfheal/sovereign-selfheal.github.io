Install guide

Install the demo on your cluster

One Ansible playbook prepares an OpenShift cluster on AWS and hands the workloads to Argo CD. This page is a short guide. The reference is the README of the ansible repository: when the two differ, the README is right.

Tested path. OpenShift 4.22 on AWS, on clusters of the Red Hat Demo Platform (RHDP), as of October 2026. Other OpenShift 4.22 clusters on AWS should work, with the differences listed in Differences on a cluster that is not from RHDP; we have not tested them end to end yet.

What you get

  • The operators of the demo, each pinned to a tested version with manual approval: OpenShift AI, OpenShift GitOps, Connectivity Link, External Secrets, Custom Metrics Autoscaler (KEDA), the NVIDIA GPU Operator and the observability operators.
  • Two GPU nodes: one for the local model (Qwen3.8 27B), one for the decision model of the privacy gate.
  • The router with its four gates, Presidio, the three demo applications with their AI SRE agents, the ticketing system, Tempo traces and Perses dashboards: all deployed by Argo CD from the gitops repository.

Requirements

WhatDetails
OpenShift4.22 on AWS, with cluster-admin. The preflight stops on other versions, because the operator versions were tested on 4.22.
GPU quota on AWSOne g7e.2xlarge (NVIDIA RTX PRO 6000 Blackwell, 96 GB) for the local model, and one g6e.2xlarge (NVIDIA L40S, 48 GB) for the decision model, in the region of the cluster. The playbook creates both nodes (200 GiB disk each). Smaller or older GPUs cannot run the local model.
ClusterA default StorageClass and the default catalogs (redhat-operators, certified-operators). The pull secret of the cluster must reach registry.redhat.io, as on every OpenShift cluster.
Workstationgit, uv, and optionally oc to log in. uv installs Ansible and the Python libraries in a local environment.
External model (optional)An OpenAI-compatible endpoint and an API key. Without it the demo runs in local-only mode: every request goes to the local model.

The two GPU instances run as long as the demo is up. Scale them to zero when you do not use the demo (see Remove).

Steps

  1. Get the code and the tools 
    git clone https://github.com/sovereign-selfheal/ansible.git
cd ansible
uv sync                                                        # Python tools from uv.lock
uv run ansible-galaxy collection install -r requirements.yml   # Ansible collections
  2. Optional: set the external model

    The settings of the external (SOTA) model stay on your machine, in a file encrypted with ansible-vault. Set all of sota_api_base, sota_model, sota_served_match and sota_api_key, or none of them.

    cp group_vars/all/vault.yml.example group_vars/all/vault.yml
ansible-vault encrypt group_vars/all/vault.yml
ansible-vault edit group_vars/all/vault.yml

# the password file that scripts/run-playbook.sh reads
mkdir -p ~/.config/sovereign-selfheal
bash -c 'umask 077; read -rs -p "Vault password: " p && printf "%s\n" "$p" > ~/.config/sovereign-selfheal/vault-pass'
  3. Log in to the cluster 
    export KUBECONFIG=~/.kube/demo.kubeconfig
# or: oc login --token=<token> --server=https://api.<cluster>:6443
  4. Run the bootstrap 
    scripts/run-playbook.sh playbooks/site.yml

    It runs six stages: preflight, the GPU nodes and the pre-pull of the model images, the operators, the optional team users, the cluster prerequisites, and the Argo CD seed. The seed waits until every Argo CD application is synced and healthy. A full run takes about 35 to 60 minutes; the first start of the local model on a new GPU node is the longest part. A second run must report changed=0.

    If AWS has no GPU capacity in a zone, the GPU machine stays in Provisioning. Give the zones in another order:

    scripts/run-playbook.sh playbooks/site.yml -e '{"gpu_node_prep_zones": ["us-east-2b", "us-east-2a", "us-east-2c"]}'
  5. Validate the install 
    cd ..                                                          # next to the ansible checkout
git clone https://github.com/sovereign-selfheal/validation.git
cd validation
uv sync
uv run ansible-galaxy collection install -r requirements.yml
uv run ansible-playbook playbooks/validate.yml                                 # read-only checks
uv run ansible-playbook playbooks/validate.yml -e validation_disruptive=true   # all checks, about 25 min

    Each check prints PASS, FAIL, WARN or SKIP. The run fails only with a FAIL. A WARN on P4 is expected: OLM proposes newer operator versions, and the pinning policy leaves them unapproved.

  6. Use the demo

    In the OpenShift console, open Observe → Dashboards in the project maas-routing, and Observe → Traces. The menu of the console has links to the router traces. To call the router yourself, take the API key of a tier and send a request to the model auto. A trace id in the request finds its decision among the logs of the two router replicas:

    KEY=$(oc get secret apikey-research-1 -n maas-routing -o jsonpath='{.data.api_key}' | base64 -d)
DOMAIN=$(oc get ingresses.config/cluster -o jsonpath='{.spec.domain}')
TRACE=$(od -An -N16 -tx1 /dev/urandom | tr -d ' \n')
curl -s https://router.$DOMAIN/v1/chat/completions \
  -H "Authorization: Bearer $KEY" -H 'Content-Type: application/json' \
  -H "traceparent: 00-$TRACE-$(od -An -N8 -tx1 /dev/urandom | tr -d ' \n')-01" \
  -d '{"model": "auto", "messages": [{"role": "user", "content": "What is the capital of France?"}]}'
oc logs -n maas-routing -l app=litellm -c litellm --tail=-1 | grep "$TRACE"   # the decision

Smaller profiles

# GPU profile without the decision model (only the GPU node of the local model)
scripts/run-playbook.sh playbooks/site.yml -e decision_model_enabled=false

# CPU profile for quick tests: a small model on CPU, no GPU node, no decision model
scripts/run-playbook.sh playbooks/site.yml -e gpu_enabled=false

Differences on a cluster that is not from RHDP

TopicOn RHDPOn another cluster
GitOps, cert-manager, Keycloak operatorsAlready installed; the playbook adopts them.The playbook installs them at the tested versions.
CertificatesLet's Encrypt certificates on the router and the API.The default self-signed router certificate: browsers and clients warn, unless you add your own certificate.
LoginA user admin through the RHDP identity provider.kubeadmin. Team users are optional (team_users in the vault): the playbook then installs Keycloak.
Argo CD UIThe user admin is an Argo CD admin.Check the RBAC of the Argo CD instance if you want to change applications from its UI.
Load balancerClassic load balancer; the playbook raises its idle timeout to 10 minutes.Same with a Classic load balancer. With a Network Load Balancer, long answers that do not stream can stop after 60 seconds.

Remove

There is no teardown playbook yet. To stop paying for the GPUs, scale both GPU pools to zero; run site.yml again to bring them back:

scripts/run-playbook.sh playbooks/20-prereqs.yml -e gpu_node_prep_replicas=0 -e gpu_node_prep_decision_replicas=0

To remove everything, delete the cluster.
